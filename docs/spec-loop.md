# Spec Loop: Problem Thesis -> PRD -> Red Team -> Build

Use this loop to turn a rough idea into a build-ready plan, pressure-test it, and iterate quickly when execution misses.

## 1) Start With a Blank Spec

Open a blank document and capture the core of the problem in bullets.

- **Problem thesis:** What is fundamentally wrong or missing today.
- **Current state:** How things work now, including pain points.
- **Desired state:** What "good" looks like after the work is done.
- **Source material:** Links or references to environment docs, code, or other canonical artifacts.

Then explicitly list:

- **Constraints:** Technical, organizational, timeline, compliance, tooling, etc.
- **Requirements:** Must-haves and non-negotiables.
- **Assumptions:** What is believed to be true but not yet proven.
- **Success criteria:** Measurable outcomes that define done.

## 2) Read It Back and Validate Thesis

Review the spec draft and confirm it actually captures the thesis of the problem.

- Remove vague language.
- Tighten scope.
- Ensure constraints and success criteria are concrete.

## 3) Generate a PRD With Claude Code (Plan Mode, Opus)

Run Claude Code in **plan mode** on **Opus**.

- Paste the structured bullet list from the spec.
- Ask it to produce a full PRD.

Output: a first-pass PRD in Markdown.

## 4) Red-Team the PRD With a Second Model

Take the PRD Markdown to another model (for example, ChatGPT in thinking mode).

Prompt framing:

- Tell it it is an **expert in the domain**.
- Tell it it is operating as a **red team**.
- Tell it explicitly that the PRD was generated by **Claude Code** (this context is important).
- Ask it to **tear the plan apart** and flag every deficiency and missed opportunity.

Save the resulting edits and critique.

## 5) Return to Agentic Build Execution

Bring the revised PRD back into your agentic harness of choice and implement.

## 6) Iterate on Misses

If execution misses:

1. Return to the PRD.
2. Adjust scope, assumptions, sequencing, or acceptance criteria.
3. Re-run the loop and build again.

This is a deliberate feedback cycle, not a one-pass planning step.

## Copy/Paste Prompts

### Prompt 1: Generate PRD (Claude Code, Plan Mode on Opus)

```text
You are a product and technical planning expert. Create a complete PRD from the structured problem notes below.

Instructions:
- Preserve the core thesis exactly; do not drift scope.
- Call out any contradictions or missing info before proposing solutions.
- Produce practical, implementation-ready output.
- Prefer explicit tradeoffs over generic guidance.

Please produce:
1) Problem statement
2) Goals and non-goals
3) Current state analysis
4) Proposed solution
5) Requirements (functional and non-functional)
6) Constraints and assumptions
7) Risks and mitigations
8) Milestones / phased rollout
9) Acceptance criteria
10) Success metrics
11) Open questions

Input notes:
[PASTE BULLET LIST HERE]
```

### Prompt 2: Red-Team PRD (Second Model, e.g. ChatGPT Thinking Mode)

```text
Act as a domain expert and a red-team reviewer.

Context:
- This PRD was generated by Claude Code.
- Your job is to aggressively critique it for blind spots, weak reasoning, and missed opportunities.

Instructions:
- Tear the plan apart constructively.
- Flag every deficiency you see: scope gaps, unstated assumptions, hidden dependencies, sequencing errors, unrealistic milestones, weak acceptance criteria, missing edge cases, security/privacy/compliance concerns, operability concerns, and poor metric design.
- Identify what the PRD gets right, but spend most effort on what is wrong or missing.
- For each issue, provide:
  1) Why it is a problem
  2) Impact if left unresolved
  3) Concrete fix
- Propose a stronger alternative plan where appropriate.
- End with a prioritized "must-fix before build" list.

PRD to review:
[PASTE PRD MARKDOWN HERE]
```
